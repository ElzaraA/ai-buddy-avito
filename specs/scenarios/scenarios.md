# Сценарии AI-buddy (черновик — утвердить на кик-оффе)

Формат: каждый сценарий = путь стажёра + критерии приёмки. Критерии приёмки → e2e-тесты и сценарий видео.

## S1. Отгул (основной сценарий с действием)
**Путь:** «Хочу взять отгул в пятницу» → помощник объясняет порядок (absence_get_policy, с пометкой «тестовая инструкция»)
→ уточняет даты → показывает черновик заявки → стажёр подтверждает → absence_create_request
→ карточка «Заявка ABS-… создана, ждёт согласования {руководитель}» → действие сохранено в истории.

Приёмка:
- [ ] без явного подтверждения заявка не создаётся;
- [ ] результат виден в чате и в /actions после перезагрузки;
- [ ] при недоступности мока — понятная ошибка, UI не зависает;
- [ ] помощник предлагает предупредить наставника, но не пишет ему сам.

## S2. Доступы и чек-лист
**Путь:** «Что мне сделать на этой неделе?» → checklist_get → список шагов + следующий шаг
→ «Запроси доступ в GitLab» → access_request → шаг переходит в `waiting` с привязкой к тикету.

Приёмка:
- [ ] экран прогресса показывает этапы, статусы, % и next step;
- [ ] после access_request статус шага обновляется без перезагрузки;
- [ ] стажёр не может менять шаги другого стажёра (403).

## S3. Вопросы о команде и инструментах
**Путь:** «Как у нас устроено код-ревью?» → kb_search → ответ со ссылками на источники.
Нет ответа в базе → «не нашёл, это лучше спросить у наставника {имя}».

Приёмка:
- [ ] каждый ответ по базе содержит источник;
- [ ] документы чужой команды / mentors_only не попадают в ответ (проверка прав);
- [ ] на вопрос вне базы помощник не выдумывает.

## Вне рамок
Финансовые операции, бенефиты с выплатами, чувствительные ПДн.
