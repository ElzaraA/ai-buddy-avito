# Сценарии AI-buddy

Формат: путь стажёра + критерии приёмки. Каждый критерий закрыт тестом (`specs/traceability.md`) и показывается в видео.

## S1. Отгул (сценарий с действием)
**Путь:** «Хочу взять отгул в пятницу» → помощник готовит черновик заявки на ближайшую пятницу, называет руководителя и советует предупредить наставника → стажёр нажимает «Отправить» → заявка ABS-… в статусе «ждёт согласования» → видна в `GET /actions` после перезагрузки.
Если дата не указана — помощник спрашивает её; ответ «2026-11-20» / «в пятницу» / «завтра» продолжает сценарий.
«Как оформить отгул?» → правила (тестовая инструкция) + имена руководителя и наставника.

Приёмка:
- [x] без явного подтверждения заявка не создаётся (только draft);
- [x] результат виден в чате и в `/actions` после перезагрузки;
- [x] при сбое LLM — понятная ошибка, UI не зависает (событие `error` + `message_done failed`);
- [x] помощник предлагает предупредить наставника, но не пишет ему сам.

## S2. Чек-лист и доступы
**Путь:** «Что мне сделать на этой неделе?» → `checklist_get` → шаги + следующий шаг → «Запроси доступ в GitLab» → черновик заявки REQ-… на GitLab → подтверждение.

Приёмка:
- [x] экран прогресса: шаги, статусы, `percent_done`, `next_step`;
- [x] доступ запрашивается только после подтверждения; ресурс берётся из вопроса;
- [x] на систему вне списка (Jira, GitLab, Grafana, Git), например «Запроси доступ в Confluence», — честный отказ без черновика;
- [x] стажёр не может менять шаги другого стажёра (403);
- [x] шаг «Получить доступы (Git, Jira, Grafana)» закрывается (`done`) только после одобрения всех трёх систем; одного GitLab мало — шаг остаётся `todo` с `sub_done: 1, sub_total: 3, missing: [jira, grafana]`, а следующий шаг в чате называет недостающие системы; всё запрошено и ждёт решения — `waiting`; отказ возвращает систему в `missing`;
- [x] подсказка «Запроси доступ в GitLab» не появляется, если заявка на GitLab уже отправлена или одобрена.

## S4. Руководитель и наставник
**Путь:** руководитель открывает входящие (`/team/actions?status=pending`) → согласует отгул стажёра с комментарием → в истории заявки видно, кто и когда решил. Наставник смотрит прогресс стажёров команды и список вопросов, на которые помощник не нашёл ответа, — и дописывает базу знаний.

Приёмка:
- [x] согласовать может только руководитель той же команды; автор, наставник и чужая команда — 403 (заявку `intern.other` согласует `lead.frontend`, `lead.backend` получает 403);
- [x] решение окончательное (повтор — 409), записано в историю;
- [x] наставник видит только свою команду; стажёру кабинет недоступен (403);
- [x] вопросы без ответа хранятся без автора, персональные данные в тексте маскируются;
- [x] в интерфейсе у каждой заявки своё поле комментария — видно, к какой заявке уйдёт комментарий.

## S5. Сигнал наставнику и ответ (двусторонняя петля)
**Путь:** стажёр: «Передай наставнику: не работает VPN» → сигнал SIG-… в кабинете команды → наставник нажимает «Разобрано» и пишет ответ (`POST /team/signals/{id}/resolve` с `{"reply"}`) → стажёр видит ответ, имя наставника и время в `GET /signals/me`.

Приёмка:
- [x] ответ ≤ 500 символов (иначе 400), персональные данные в ответе маскируются; пустое тело тоже закрывает сигнал;
- [x] сигнал чужой команды — 404; `GET /signals/me` — только свои сигналы, новые сверху; не стажёру — 403;
- [x] ответ сохраняется в снимке состояния.

## S6. «Пульс», достижения и «Сэкономлено наставнику»
**Путь:** стажёр отмечает самочувствие (1..5) → наставник видит «Пульс команды» с риском и трендом → руководитель видит в сводке честную экономию времени наставника.

Приёмка:
- [x] «сегодня» — по Москве (`TZ_NAME`, запасной UTC+3);
- [x] `questions_closed` = ответы по базе с источником + термины словаря + подтверждённые заявки; меню, small talk, чек-лист, черновики и отмены не считаются;
- [x] достижения выводятся из состояния и обнуляются демо-сбросом.

## S7. Вопросы вне базы и безопасные подсказки
**Путь:** «Как оформить командировку?», «Как подключить ДМС?», «Где парковка?», «Отпуск по уходу за ребёнком» → честный отказ «Не нашёл ответа…» с именем наставника, без чужого фрагмента (раньше — про доступ к Jira).

Приёмка:
- [x] золотые кейсы `OT-*` — отказ; 152 формулировки `intents_test.go` не сломаны;
- [x] подсказка «Передай наставнику: …» не повторяет prompt injection, вопрос о зарплате и реплику с ПДн; после отказа про зарплату — «Кому написать про условия стажировки?».

## S8. Демо-режим
**Путь:** перед показом жюри — «Сбросить демо» (`POST /demo/reset`) → все заявки, сигналы, «Пульс», пробелы, счётчики и диалоги исчезают, чек-листы — как при свежем старте. `GET /demo` показывает режим и тип модели (mock/real).

Приёмка:
- [x] сброс доступен только при `DEMO_MODE=true` (иначе 404) и любому демо-пользователю, под лимитом записи;
- [x] после сброса нумерация заявок начинается с ABS-000001, старая сессия чата недоступна.

## S3. Вопросы о команде и инструментах
**Путь:** «Какой стек у команды Backend?» / «Где смотреть логи?» → ответ из базы со ссылкой на источник. Нет ответа в базе («Сколько платят?») → «не нашёл, лучше спросить наставника» с именем наставника команды стажёра (для backend — Иван Петров, для frontend — Анна Козлова). Наставник и руководитель в отказах и черновиках всегда берутся по команде пользователя; наставнику и руководителю помощник советует HR BP, а не «наставника».

Приёмка:
- [x] каждый ответ по базе содержит источник;
- [x] документы чужой команды и mentors_only не попадают в ответ;
- [x] на вопрос вне базы помощник не выдумывает (отказ даже если LLM «знает»).

## Вне рамок
Финансовые операции, бенефиты с выплатами, чувствительные ПДн. Все данные и инструкции — синтетические.
