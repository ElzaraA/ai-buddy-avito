# Кик-офф: первые 2–3 часа

## 0:00–0:30 — Сценарии (все)
- Пройтись по чек-листу стажёра Авито, каждый называет 2–3 «боли» первых недель.
- Голосованием выбрать 3 сценария → `specs/scenarios/scenarios.md`.
- Для каждого написать путь и 3–4 критерия приёмки. Это же потом сценарий видео.

## 0:30–1:45 — Контракты (все вместе, один экран)
Правило: сначала договорились, потом пишем код.
1. **openapi.yaml** (фронт + бэк ведут, остальные проверяют): эндпоинты, схемы, коды ошибок.
2. **agent-api.md** (бэк + агент): что backend передаёт агенту, какие события возвращаются.
3. **mcp-tools.json** (агент + интеграции): инструменты, входы/выходы, ошибки, как передаётся пользователь.
4. **schema.sql** (бэк): таблицы под сценарии.
Проверка контрактов: «прогоните» S1 устно по шагам — кто кому что шлёт. Пробелы всплывут сразу.

## 1:45–2:30 — Репозиторий и договорённости
- Монорепо, `main` защищён, работа в ветках `feat/<area>-<name>`, PR с 1 ревью.
- Изменение контракта = отдельный PR в `specs/contracts/` + сообщение в чат команды.
- Каждый в своей папке поднимает «пустой» сервис, который отвечает по контракту фейковыми данными
  (план; в итоге сервисы объединены в один Go-бэкенд, папки-заготовки удалены):
  - frontend — MSW-моки по openapi.yaml;
  - backend — заглушки хендлеров;
  - agent — фейковая LLM (в итоге `LLM_MOCK=true`);
  - mcp-mocks — статичные ответы.
- `docker compose up` должен подниматься уже к концу кик-оффа (пусть всё и на заглушках).
- Тесты + покрытие с первого коммита: Go `go test -cover`, фронт Vitest `--coverage`
  (Python в итоге не понадобился).
