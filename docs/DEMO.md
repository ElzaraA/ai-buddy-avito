# Сценарий демо-видео (3–4 минуты)

Все данные тестовые. Демо идёт на mock-LLM (`LLM_MOCK=true`, ключ не нужен), поэтому ответы
повторяются от записи к записи.

## Подготовка к записи

```bash
docker compose down -v          # чистое состояние: удаляет том buddy-state со старыми заявками
cp .env.example .env
docker compose up --build
```

- Интерфейс: http://localhost:5173, пользователь переключается в шапке («Тестовый пользователь»):
  Стажёр Backend, Второй стажёр Backend, Стажёр другой команды (frontend), Наставник Backend,
  Руководитель Backend, Руководитель Frontend.
- Порты опубликованы только на `127.0.0.1`: открывайте интерфейс на том же ноутбуке, с которого идёт запись;
  с телефона или соседнего ноутбука по сети он не откроется — так задумано.
- Во втором окне откройте терминал для MCP-части (шаг 0:50 ниже). Команды должны выполняться в `bash`.
  На macOS сначала выполните `bash`: в zsh по умолчанию `#` в интерактивном режиме не считается комментарием.
- Масштаб браузера 110–125 %, чтобы текст читался на видео.

## Чего избегать на записи

- Не берите в вопросе об отгуле прошедшую дату: помощник её не оформит и переспросит.
- Не перезапускайте контейнеры с `-v` между дублями одной сцены: прогресс стажёра обнулится.
- Если запись идёт на реальной модели (`LLM_MOCK=false`), при её сбое отвечает резервная модель,
  ответ помечается `"degraded": true` и выделяется в чате — так и задумано.

Ответы на частые вопросы жюри — `docs/FAQ.md`.
